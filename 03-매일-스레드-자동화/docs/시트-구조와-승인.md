# 시트 구조와 승인

운영 시트의 탭은 사용법, 주제목록, 검토함, Make설정, 전체설계도입니다.

## 실제 헤더

| 탭 | 실제 열 |
| --- | --- |
| 주제목록 | 순서 / 주제 / 주요 독자 / 다룰 내용·관점 / 사용 여부 / 주제 검토 / 첫 문장 예시 / 작성 전 확인할 근거 |
| 검토함 | 글 ID / 게시 예정일 / 주제 / 소주제 / 본문 · 직접 수정 / 승인 상태 / 처리 상태 / Buffer 접수 ID / 게시 URL / 메모 |

## 구현 전에 추가할 필드

- 주제목록: 분야 ID, 주제 고유 ID
- 검토함: 공식 출처 URL, 출처 확인일, 적용 조건, 사실 확인 상태
- 게시 요청·최종 게시 확인 시각 등 운영 기록

위 필드는 설계상 추가 예정이며 원본 시트에는 아직 만들어지지 않았습니다.

## 상태와 승인

- 주제 검토: 검토대기 / 채택 / 수정필요 / 제외
- 사용 여부: 사용 / 사용안함
- 게시글 승인: 검토대기 / 승인 / 보류
- 게시글 처리: 미전송 / 처리중 / 전달완료 / 결과확인필요 / 오류 / 게시확인

주제 채택은 게시글 승인이 아닙니다. 최종 본문과 출처를 확인한 뒤 개별 게시글을 승인해야 합니다.

본문 수정 시 승인을 자동 해제하는 코드는 없습니다. 수정할 때는 **검토대기 → 수정 → 재승인** 순서를 적용합니다. Apps Script onEdit을 통한 자동 해제는 향후 구현 항목입니다.

게시 필터는 오늘 날짜 + 승인 + 사실 확인 완료 + 미전송 + Buffer 접수 ID 없음입니다. 현재 샘플은 게시 날짜가 비어 있어 게시 대상이 아닙니다.

## 사용 안내 보관본

| Threads 아침 게시 · 사용 안내 | 내용 |
| --- | --- |
| 현재 상태 | 검토용 시트만 준비됨. Make·OpenAI API·Buffer·Threads 연결 및 자동화 활성화는 아직 하지 않았습니다. |
| 시간대 | 한국 시간 / Asia/Seoul |
| 1. 주제 정하기 | ‘주제목록’ 탭에 후보 주제 30개와 Threads 말투의 첫 문장 예시를 넣었습니다. 주제 검토=채택, 사용 여부=사용으로 바꾸면 연결 후 순환 대상이 됩니다. 주제 채택과 게시글 승인은 별개입니다. |
| 2. 순환 방식 | 사용 중인 주제를 순서 숫자대로 1→2→3→…→1로 반복합니다. 같은 주제에서도 새로운 소주제와 예시로 작성합니다. |
| 3. 매일 오전 4시 | 연결 후 Make가 초안 1개를 작성해 ‘검토함’에 검토대기로 저장합니다. |
| 4. 내가 검토 | ‘검토함’의 본문을 직접 수정한 뒤 승인 상태를 ‘승인’으로 바꾸세요. 샘플 행은 게시 예정일이 비어 있어 게시 대상이 아닙니다. |
| 5. 매일 오전 7시 이후 | 연결 후 게시 자동화가 오늘 날짜의 승인된 글을 확인합니다. 7시 전 승인: 7시 이후 첫 실행에 전달. 7시 후 승인: 다음 확인 때 전달. |
| 승인 확인 간격 | 오전 7시~오후 11시 55분, 5분 간격을 제안합니다. 실제 실행 시간은 자동화 서비스의 처리 지연이 있을 수 있습니다. |
| 미승인·보류 처리 | 승인하지 않은 글은 게시하지 않습니다. 전날 미승인 글도 다음 날 자동으로 올리지 않습니다. |
| 승인 후 수정 | 수정하려면 먼저 ‘검토대기’로 바꾸고 본문 수정 후 재승인하세요. 현재 시트에는 승인 자동 해제나 편집 잠금 코드가 없습니다. |
| 중복 방지 | Make 연결 시 날짜별 초안 중복 생성 방지, 실행 동시성 1, Buffer 접수 ID 저장을 설정합니다. |
| 전달완료의 의미 | Buffer가 접수했다는 뜻이며 Threads 실제 게시 성공과는 다릅니다. 최종 결과는 Buffer에서 확인하세요. |
| 필요 계정 | Google, Make, OpenAI API, Buffer, Threads. OpenAI API 요금은 ChatGPT 구독과 별도입니다. |
| 연결 순서 | Buffer↔Threads 연결 → Make↔Google Sheets/OpenAI/Buffer 연결 → ‘Make설정’ 탭에 따라 두 시나리오 구성 → 샘플 테스트 → 활성화 |
| 주의할 입력 | 고객 실명·기밀은 입력하지 마세요. 실제 경험, 고객 성과 수치, 최신 정책은 확인한 자료가 있을 때만 사용합니다. |
