# Make 구현 명세

실제 Make 가져오기용 blueprint JSON은 아직 없습니다. 아래는 초기 수동 구성 명세입니다. 이후 추가된 9개 분야 순환과 사실 확인 단계는 [전체 설계도](전체설계도.md)를 우선 적용하세요.

| 항목 | 설정할 내용 |
| --- | --- |
| 준비 상태 | 이 탭은 Make에 입력할 구현 명세입니다. 실제 시나리오는 아직 생성·활성화되지 않았습니다. |
| 연결 1 | Buffer에 Threads 계정을 추가하고 게시 권한을 허용합니다. |
| 연결 2 | Make에서 Google Sheets 계정, OpenAI API 키, Buffer 계정을 연결합니다. API 키는 시트에 적지 않습니다. |
| 전역 설정 | Make와 Buffer 시간대 Asia/Seoul. 계정 1개 / 하루 최대 1개. 게시 시나리오 동시 실행 수 1 또는 순차 처리 사용. |
| A · 실행 | 매일 오전 04:00 / 한국 시간 |
| A · 글감 읽기 | ‘주제목록’에서 주제 검토=채택 AND 사용 여부=사용인 행만 순서 숫자 오름차순으로 읽습니다. 대상이 없으면 종료합니다. 제목·관점·첫 문장 예시·작성 전 확인할 근거를 AI에 전달합니다. |
| A · 순환 상태 | Make Data Store에 마지막 선택 주제의 고유 키를 저장합니다. 그 다음 사용 주제를 선택하고 끝이면 처음으로 돌아갑니다. 안정적인 키로 행 번호 대신 고유한 주제 키를 운영 설정에 매핑하세요. |
| A · 중복 실행 방지 | 계정+한국 날짜를 초안 키로 사용합니다. ‘검토함’에 당일 초안이 이미 있으면 새로 작성하지 않고 종료합니다. 초안 저장 성공 후에만 순환 상태를 갱신합니다. |
| A · 이전 글 읽기 | 최근 30개 초안·게시글과 같은 주제의 최근 글을 함께 가져와 AI에 전달합니다. 기록이 더 많아지면 주제별 요약 이력을 추가합니다. |
| A · 생성 | 아래 작성 지시문과 선택 주제를 OpenAI에 전달합니다. 생성 결과의 소주제·본문을 길이와 중복 관점으로 검토하고 실패하면 최대 2회 재작성합니다. |
| A · 검토함 저장 | 글 ID, 오늘 게시 예정일(YYYY-MM-DD), 주제, 소주제, 본문, 승인 상태=검토대기, 처리 상태=미전송으로 새 행을 저장합니다. 사용자가 수정한 기존 초안을 덮어쓰지 않습니다. |
| B · 실행 | 매일 오전 07:00~23:55, 5분 간격. Make 요금제가 이 간격을 지원하는지 확인합니다. 실행 중첩은 막습니다. |
| B · 필터 | 게시 예정일=한국 날짜의 오늘 AND 승인 상태=승인 AND 처리 상태=미전송 AND Buffer 접수 ID가 비어 있음 AND 본문이 비어 있지 않음. |
| B · 하루 1개 | 동일 계정·오늘 날짜에 처리중/전달완료/결과확인필요 글이 있으면 다른 글을 보내지 않습니다. 조건을 만족하는 행이 여러 개면 1개만 선택합니다. |
| B · 보내기 직전 | 행을 다시 읽어 승인·날짜·상태·최종 본문을 확인한 뒤 처리중으로 변경합니다. 승인된 뒤 수정할 때는 사용자가 먼저 승인 취소 후 재승인하는 운영 규칙을 적용합니다. |
| B · Buffer 전달 | Buffer 게시 모듈에서 Threads 계정을 선택하고 승인한 본문 그대로 전달합니다. 오전 7시 이후 실행이므로 즉시 게시 옵션을 사용합니다. |
| B · 정상 접수 | Buffer 접수 ID를 먼저 기록하고 처리 상태=전달완료로 변경합니다. 이것만으로 게시확인 상태로 바꾸지 않습니다. |
| B · 오류 처리 | 접수 여부가 불확실한 타임아웃 등은 결과확인필요로 기록하고 자동 재전송하지 않습니다. Buffer에서 확인 후 운영자가 재처리합니다. 확실한 거절은 오류로 기록합니다. |
| B · 당일 종료 | 23:55 이후 승인한 글은 자동으로 다음 날 게시하지 않습니다. 다음 날 게시가 필요하면 게시 예정일을 바꾸고 다시 검토·승인합니다. |
| 주제 변경 | 사용/사용안함 및 순서를 다음 초안부터 반영합니다. 이미 작성한 초안은 자동으로 바꾸지 않습니다. |
| 본문 수정·재승인 | 검토대기 → 본문 수정 → 승인. 현재 템플릿에는 자동 승인 해제 코드가 없으므로 이 순서로 운영합니다. |
| 확인 1 | 승인하지 않은 샘플은 Buffer에 전달되지 않아야 합니다. |
| 확인 2 | 7시 전 승인한 테스트 글은 7시 이후 첫 실행에, 7시 후 승인한 글은 다음 확인 때 전달되어야 합니다. |
| 확인 3 | 연속 실행해도 같은 글이 한 번만 전달되어야 하며, 어제 글·보류 글은 전달되지 않아야 합니다. |
| 확인 4 | 주제는 사용 중인 항목만 순환해야 하고, 같은 주제가 돌아와도 소주제·사례가 달라야 합니다. |
| 확인 5 | Buffer 접수 후 시트 기록에 실패한 경우에도 재전송하지 않고 접수 이력을 대조해야 합니다. |
| 활성화 순서 | 주제 확정 → 계정 연결 → 두 시나리오 구성 → 비공개 실행 기록으로 승인 필터 검사 → 사용자 승인한 실제 테스트 게시 1개 확인 → 예약 활성화. |

작성 지시문은 [별도 파일](../prompts/게시물-작성.md)에 보관했습니다.
